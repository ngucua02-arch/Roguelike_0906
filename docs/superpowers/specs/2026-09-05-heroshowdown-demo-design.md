# HeroShowdown（英雄守卫战 demo）设计文档

日期：2026-09-05
状态：已与需求方逐节确认（玩法 / 架构 / 路线图）

## 1. 背景与目标

参照 TapTap 手游《英雄大对决》（肉鸽 + 轻策略塔防，Q 版，开战前投币触发随机事件），
做一个**核心循环可玩 demo**：实时塔防战斗 + 局内肉鸽事件循环。

- 参照游戏：<https://www.taptap.cn/app/822126>
- 引擎：Godot 4.7（GDScript），PC 窗口优先（输入层抽象，保留多端导出可能）
- 美术：Kenney 免费 CC0 像素素材（塔防包为主，数据驱动 sprite 坐标，不阻塞开发）
- 项目位置：`G:\Zcode\project\HeroShowdown`（独立新仓库；
  前作 `Roguelike` 保留为架构模式参考，不共享代码）
- 开发策略：**垂直切片**——先让整条循环每环最简成立，再逐环加深；
  每个 phase 结束都是"GUT 全绿 + 可玩"状态。

**明确不做（YAGNI，demo 阶段）**：抽卡、局外养成、种族/阵营共鸣、
战斗前小游戏（抛硬币/弹珠/摇奖机）、提前开波/卡波奖励、飞行单位、
多地图布局、音效（可选）、联机。以上进入"验证好玩后再扩"清单。

## 2. 玩法设计

### 2.1 单局结构（一条冒险 = 5 关）

```
第1关:   备战(初始金币买英雄+布阵) → 实时战斗 → 结算
第2~5关: 肉鸽事件 → 备战(商店+调整布阵) → 实时战斗 → 结算
                                   ↓
                     城堡HP>0 → 下一关；=0 → 冒险失败
第5关守住 → 通关结算（总击杀 / 剩余城堡HP / 用时）
```

### 2.2 战斗规则（实时塔防）

- 地图：格子网格约 16×10；预置一条弯折路径；怪物沿路径走向城堡；
  只有路径旁的格子可部署英雄。
- 英雄：部署到合法格子后自动索敌攻击（射程圈可视化）；每英雄 1 个主动技能，
  玩家点按钮/热键释放，冷却制。玩家操作 = 技能时机 + 金币分配。
- 波次：每关 6 波；波与波之间自动休整约 5 秒（时长进数据表可调）；
  最后一波含精英或 boss。
- 局内经济：击杀掉金币；金币买新英雄、给已部署英雄升级
  （每次升级在 攻击力/攻速 二选一）。
- 城堡：10 HP；每漏 1 小怪扣 1，漏 boss 扣 3；归零即冒险失败。

### 2.3 Demo 内容量

| 类别 | 数量 | 内容 |
|---|---|---|
| 英雄 | 5 | 剑士(近战快攻/旋风斩·近身范围伤害)、弓手(远程单体/箭雨·范围持续)、法师(远程溅射/冰环·范围减速+伤害)、炮手(超远程慢速高伤/轰击·大范围高伤)、牧师(范围治疗友军/圣盾·短时减伤) |
| 怪物 | 5+boss | 哥布林(快·脆)、兽人(标准)、疾行狼(极快)、石魔(慢·高血·减伤)、萨满(周期性治疗周围怪)、巨魔王(boss·高血·踩踏眩晕英雄数秒) |
| 关卡 | 5 | 同一地图布局，主题色/波次表递进：森林×2 → 荒漠×2 → 堡垒(含 boss) |
| 肉鸽事件 | 8 | 强化卡 3 选 1 ×6(全局攻击%/攻速%/开局金币%/城堡+5HP/技能CD-%/随机英雄升1级)、精英挑战(本关怪+30%强度·胜利金币×2)、免费宝箱(随机金币/临时强化) |

数值全部进 `resources/` 数据表，首版数值在 P5 统一调平衡
（目标：默认数值下首遍通关率约 50-70%）。

## 3. 技术架构

延续前作已验证的"规则层/表现层分离 + 数据驱动 + 事件流"模式，适配实时。

### 3.1 分层

```
src/view/ + src/ui/   表现层：渲染实体快照与事件流、动画、飘字、特效；
                      输入(布阵拖放/技能按钮/×2加速)；不改规则层状态
src/autoload/game.gd  调度层：全局流程状态机(主菜单→冒险→关卡[事件/备战/战斗]→结算)；
                      每物理帧累积真实时间，按固定 20tps 步进规则层，广播事件
src/core/             规则层：纯 GDScript，无场景依赖，GUT 全测
  battle/  BattleSim(20tps 确定性步进)、Entity、Targeting、Combat、
           SkillSystem、WaveDirector(波次调度)、Grid/Path
  run/     RunState(一条冒险状态)、RunEventSystem(肉鸽事件效果注入)、
           ShopEconomy(局内金币/买卖/升级)
  def/     HeroDef / MonsterDef / WaveDef / LevelDef / EventDef 纯数据类
```

### 3.2 数据驱动（`resources/` 下 .tres，调平衡不碰代码）

- `heroes/*.tres`：数值 + 技能 + 索敌类型 + sprite 坐标
- `monsters/*.tres`：血/速/防/特性/金币掉落/sprite 坐标
- `waves/*.tres`：每波怪物组成、出怪间隔、波次奖励
- `levels/*.tres`：波次表引用、主题色、路径 waypoints、初始金币
- `events/*.tres`：事件文案 + 效果参数（效果枚举 + 数值）

### 3.3 数据流（单向往下，事件单向往上）

```
输入(放英雄/放技能/加速)
  → game.gd → 规则层 BattleSim.step()/RunState
  → 输出事件字典流 {type, data}
    (spawn/攻击/受伤/死亡/掉金币/漏怪/波开始/波结束/阶段切换/胜负)
  → 表现层消费播放
```

规则层不持有任何 Node 引用 → 可 headless 跑完整冒险做自动化测试。

### 3.4 错误与边界（规则层状态机保证幂等）

- 技能对已死/出屏目标：自动无效，不结算不退 CD（CD 在释放成功才开始转）
- 金币不足购买：请求层拒绝，广播 `buy_failed` 事件由表现层提示
- 城堡 0HP：战斗立即锁定，胜负结算只触发一次
- 部署非法（路径格/已占用格/英雄已部署/金币不足）：请求层拒绝
- 事件池：同一冒险内不重复抽取

### 3.5 测试策略

- GUT 规则层单测：索敌排序、伤害/护甲公式、技能效果(伤害/溅射/减速/治疗/护盾)、
  波次推进、经济收支、事件效果注入、胜负边界、状态机幂等
- Headless 冒烟：自动随机决策打完整 5 关冒险，断言无崩溃、状态机走完、可通关
- 延续前作测试工作流（`gut_cmdln` + `gutconfig`）

## 5. 风险与对策

- **实时战斗手感不达预期**：P1 结束即用最糙版本验证"守城是否成立"，
  不成立时尽早调整（如波次节奏/技能权重），沉没成本最低。
- **Kenney 素材风格与 Q 版预期有差距**：素材数据驱动（坐标表），
  后续可整包替换而不动逻辑。
- **20tps 确定性模拟的浮点误差**：demo 阶段不做回放/联机，浮点足够；
  测试断言用容差比较。若未来需要回放，再升级定点数。
